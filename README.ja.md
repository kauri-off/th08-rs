# th08: 東方永夜抄を Rust でゼロから作り直す

[![Check](https://github.com/kauri-off/th08-rs/actions/workflows/check.yml/badge.svg?branch=master)](https://github.com/kauri-off/th08-rs/actions/workflows/check.yml)

[English](README.md) · [Русский](README.ru.md)

東方永夜抄 ~ Imperishable Night（上海アリス幻樂団、2004年）を Rust で再実装した、非公式のファンプロジェクトです。上海アリス幻樂団とは
関係がなく、ゲームデータは含まれていません。遊ぶにはゲーム本体が必要です。移植版は本体の `th08.dat` と `thbgm.dat`
を読み込みます。

## 遊び方

1. **ダウンロード**：[リリースページ](https://github.com/kauri-off/th08-rs/releases)から、Windows は `.exe`、Linux は
   `.AppImage`（`chmod +x` してから実行）、Android は `.apk` を入手します。[ブラウザ版](https://kauri-off.github.io/th08-rs/)は
   インストール不要です。
2. **お手持ちのゲームから** `th08.dat` と `thbgm.dat`（あれば `th08.pak` / `thbgm.pak`）を用意します。移植版には
   ゲームデータが含まれていないため、東方永夜抄を所有している必要があります。
3. **置き場所：**
   - Windows / Linux：コピーは不要です。初回起動時にランチャーでゲームのフォルダを選びます。
   - Android（現時点）：ファイルマネージャーか adb で
     `/storage/emulated/0/Android/data/org.th08.port/files/game/` にコピーし、**再確認** をタップします。
4. **セーブ、リプレイ、`port.cfg`** の場所は `%APPDATA%\th08\`（Windows）、`~/.config/th08/`（Linux）、
   アプリの専用領域（Android。アンインストールすると消えます）です。
5. **翻訳：** ランチャーの **翻訳** パネルで Touhou Patch Center から翻訳をダウンロードすると、お手持ちのゲームデータ
   から端末上でパックが作られます。その後 **ゲーム内テキストの言語** で選びます。

Android 版には 3 つのチャンネルがあります。`release`（`org.th08.port`）が GitHub で配布しているもので、`dev` と
`debug` はローカルビルドです。詳細、正確なパス、操作方法：[docs/PLAYING.md](docs/PLAYING.md)（英語）。

## 目指したこと

原作に「似ている」移植ではなく、原作と「同じ」移植を作りたいと考えました。基準は厳しく、同じ入力を与えたら、
フレーム単位でも乱数の呼び出し単位でも、まったく同じゲーム展開にならなければなりません。そうなれば、原作で
録ったリプレイがそのまま移植版でも再生できます。

もう一つ、クリーンな書き方にもこだわりました。Rust のコードを書く側は、原作の実行ファイルを一切見てはいけない
というルールです。

## 作り方

作業は、典型的なクリーンルーム方式に従って二つの「部屋」に分けました。

- **ダーティルーム**は `th08.exe` を Ghidra と実行時プローブで調べました。プローブはプロキシの `d3d8.dll` で、
  毎フレームすべての描画呼び出し、乱数呼び出し、ゲーム状態を記録します。成果物はコードではなく、17 本の仕様書
  （`specs/`、約 1 万行）です。中身は文章、表、構造体のレイアウト、定数、短い擬似コードです。
- **クリーンルーム**は、その仕様書だけを見て Rust のコードを書きました。仕様が足りないときは推測しません。質問を
  書き出してダーティルームに戻し、答えはまず仕様書に反映されました。

両方の部屋の作業のほとんどは AI エージェント（Claude）が行いました。私の役割は指揮です。作業を小さなタスクに分け、
二つの部屋を分離し、何を正解とするかを決め、結果を確認しました。期間は 2026年10月16日からの約二週間半で、
実装タスクはおよそ 190 件、リバースエンジニアリングへの質問は約 70 回でした。

## 「同じ」をどう確かめたか

原作を Wine で動かし、移植版に同じ入力を与えて、毎フレームのゲーム状態のトレースと描画ログを比較しました。

- ゲーム本体のデモプレイ
- 私自身が録ったプレイ（1 面から最後まで）
- コミュニティのリプレイ。約 13,000 個の `.rpy` を集め、そのうち 1,010 個を両方のプログラムで再生しました。

何よりも大事にしたルールがあります。**トレースは移植版がどこでずれているかを示すだけで、ゲームがどう動くかを
決めるものではない。** それを決めるのは仕様書だけです。トレースと移植版が食い違い、仕様書で説明できないときは、
数字を合わせるだけの修正はせず、ダーティルームへの質問にしました。

## 結果

- **ゲームロジックはビット単位で一致します。** 1,010 個のコミュニティリプレイと録画したプレイはすべて原作と
  一致しました。全フレーム、全乱数呼び出し、スコア、アイテム、被弾まで同じです。
- **描画は見た目で一致します。** 残った描画の差はすべて、サブピクセルの浮動小数点丸めやローダーが終わる
  フレームなど、原因が分かっていて許容できるものだと突き止めました。
- **ゲームはすべて揃っています。** Extra を含む全ステージ、12 種類すべてのショット、ボムとラストスペル、
  スペルカード、会話、夜の時計、メニュー、オプション、リプレイ、`score.dat`、エンディング、ミュージックルーム、
  BGM。
- **動作環境は** Windows、Linux、Android（ネイティブ）、そしてブラウザ（WebAssembly、WebGPU または WebGL2）です。

## 現在

移植は完成しています。今は、慣用的な Rust への書き直しをしています。

- グローバルな状態を、複製できる一つの `World` にまとめる
- 描画をコマンドのリストにする
- コアをウィンドウ、サウンド、ファイルシステムから切り離す

書き直しの間、挙動は固定しています。一歩進むごとに、移植版を書き直し前の自分自身とリプレイ集の両方と照合します。
配置を自由に変えられるタッチ操作ボタン付きの Android 版は公開済みで、次はスマートフォン向けのブラウザ版です。

## ビルド

ビルド済みのファイルは[遊び方](#遊び方)を参照してください。自分でビルドするには、安定版の Rust が必要です。

```sh
cargo run --release -- "/path/to/TH08 - Imperishable Night"
```

操作は原作と同じです。矢印キーで移動、`Z` でショット、`X` でボム、`Shift` で低速、`Esc` でポーズ。すべての設定は
`th08 --help` で確認できます。パッケージ（AppImage、Windows の exe とインストーラー、Android の APK、ブラウザ版）は
`cargo xtask dist --target <linux-appimage|windows-exe|windows-nsis|android-apk|web>` で作れます。オプションは
`cargo xtask dist --help` で確認できます。

## リポジトリの構成

| パス | 内容 |
|---|---|
| `specs/` | 仕様書。挙動についての唯一の正解 |
| `src/` | アプリ本体：ゲームウィンドウ、ランチャー、設定、プラットフォーム（パッケージ `th08`、実行ファイル `th08`） |
| `crates/` | `th08-formats`（ファイル形式）、`th08-core`（ゲームロジック）、`th08-render`（wgpu）、`th08-audio`（cpal、MIDI）、`th08-tools`（トレース・描画ログのツール、`src/bin/` に実行ファイル） |
| `re/` | リバースエンジニアリング用ツール：フォーマットのダンプ、Ghidra スクリプト、実行時プローブ、プレイの録画 |
| `docs/` | 進捗、設計判断、書き直しのアーキテクチャ（[目次](docs/README.md)） |

| `web/`, `packaging/`, `xtask/` | ブラウザ用フロントエンド、パッケージング用ファイル、`cargo xtask dist` |

貢献の方法：[CONTRIBUTING.md](CONTRIBUTING.md)（英語）。
