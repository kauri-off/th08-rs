# I18N — translated game text (en, ru) and a trilingual launcher (ja, en, ru)

Research + design, 2026-11-04. Builds on the content / mod boundary of [ARCH_SUMMARY.md](ARCH_SUMMARY.md) (Vfs, `TextRef`, layout policy, fonts,
images) and [ASSETS_FORMAT.md](ASSETS_FORMAT.md) (AS1 pack format). Japanese stays the original. Nothing here changes logic: every trace, session,
batch and score.dat byte stays identical in every language.

## 1. Findings

### 1.1 thcrap (engine) and thcrap-tsa (base patches)

- `thpatch/thcrap` (the engine) is **Unlicense** (public domain). `thpatch/TouhouPatchCenter` (the MediaWiki
  extension that turns wiki pages into patch files) is Unlicense too. `thpatch/thcrap-tsa` (base_tsa etc.) has **no
  licence file** (GitHub reports none). We use none of its code. The engine is Win32 detours (binhacks, breakpoints)
  and does not apply to a source port. We only read its **file formats** as documentation of the data.
- th08 engine data in thcrap-tsa: `base_tsa/th08.js` (binhacks + breakpoints, `formats: {msg: msg08, anm: anm06}`),
  `base_tsa/th08.v1.00d.js` (addresses for 1.00d), `base_tsa/th08/stringlocs.v1.00d.js` (exe string RVA → string id,
  e.g. `Rxb8f1c: "th07 Menu Start"`), `base_tsa/formats.js` (`msg08`: XOR 0x77; ops 3 = hard_line, 16/19/20 =
  auto_line, 4/15 = auto_end), `base_tsa/th08/text.anm` (thcrap's own text.anm patch: a logic key for us, so we skip it).
- The breakpoints that matter for th08 also show *where* the text lives: `spell_name` (+ `#practice_menu`, `#result`,
  `#practice_menu_page`, `#practice_menu_details`, `#replay`), `spell_comment_line#1/#2`, `spell_owner`,
  `music_title`, `music_title#nowplaying`, `music_cmt`, `file_load`/`file_loaded` (jdiff patching of msg/end),
  `ascii_params` (`CharWidth 13.0`: Latin ascii.png uses narrower glyph cells). Binhacks: `spell_align`,
  `menu_desc_align`, codecave `stage_result_align` replace the byte-length centring/right-alignment with
  `GetTextExtent` (measured pixel width). That is the mod design's layout rule. `sprintf_*` / `strings_sprintf` turn exe
  format strings into lookups. `unpatch_font` resets the English font size.
- Fonts/encoding in thcrap: the `win32_utf8` detours make SJIS "A" Win32 calls accept UTF-8. `textdisp.cpp` hooks
  `CreateFont*` and forces the patch font (lang_ru `th08.js` = `{"font": "Aroania"}`; lang_ru ships
  `th08/MyriadPro-Cond.otf`). `layout.cpp` adds GDI layout markup (`<l$…$…>` tab stops, ruby). The msg patcher
  (`th06_msg.cpp`, shared by th06–th08) **inserts extra text ops** when a box has more lines than the original, and
  moves speech bubbles. That changes msg bytes, so **we must not copy it** (msg is a logic key, §2.1).

### 1.4 Licence compatibility — recommendation

CC BY-SA 4.0 → GPLv3 is one-way compatible: CC declared it in 2015, so a BY-SA 4.0 adaptation may be relicensed
under GPLv3. Shipping it *next to* GPL code is plain aggregation and needs no compatibility at all. The licence is
therefore **not** the blocker. ZUN's copyright in the source text and images is. The port's rule (no game data in the
repo; the user supplies th08.dat) should hold for translations too. **Recommendation:**

1. No translated game text and no images in git. The repo ships only the GPL **converter** (`th08-tools
   thcrap-import`) and the pack loader.
2. A translation is a separate **presentation pack**. It is built on the user's machine from a local thcrap
   `lang_xx` directory or downloaded by the tool from `srv.thpatch.net` (opt-in, prints the source + licence). The
   pack carries `ATTRIBUTION.txt` (TPC + contributors + CC BY-SA 4.0 link + "converted by th08-tools, lines
   refitted") and keeps CC BY-SA 4.0 for its own text.
3. Personal packages (APK/AppImage/NSIS, `project-local-packages`) may bundle a pack, like th08.dat, with
   ATTRIBUTION.txt inside. No public release with bundled packs.
4. Fonts in a pack: OFL only (Noto Sans / PT Sans Narrow / M PLUS 1). Never copy thpatch's font files blindly.

## 2. Game text design

### 2.1 Invariant: presentation only

- Logic keeps reading msg / ecl / end / musiccmt bytes through `LogicView` (core `content.rs`). A text pack is
  `Class::Presentation`: it can never override a logic key (`.msg .dat .end .ecl .anm …` are rejected at
  mount), it is **not** in the logic `Fingerprint`, and it is not compared in session metadata. Optional
  informational `present: lang=ru pack=<hash>` line, never checked.
- Line count and timing come from logic (msg op 4 waits, one VM + wait per ending line, 10 §5.2 / 16 §1.3). A
  translation fills the **existing** line slots. It never adds or drops ops. This is the deliberate difference from
  thcrap's msg patcher (§1.1).
- score.dat, replays and spell-practice data keep the Japanese bytes. Display goes through `TextRef`, so names show
  translated, while files stay byte-identical across languages.

### 2.2 Where text enters the renderer today

`ResCmd::Text(TextCmd)` (core `drawlist.rs:338`, `text: SjisString`) is recorded at six sites: `hud.rs:499`
(dialogue, 10 §6), `gui.rs:276` (spell plate / bonus, 07 §11.1), `ending.rs:436` (16 §1.3), `musicroom.rs:129`
(16 §5.1), `menulist.rs:517` (16 §6.3/§6.5) and `menu.rs:455` (descriptions, 12 §2.2). `th08-render/text.rs`
rasterises it with a system font (native) or the canvas (web). ASCII-sheet text (`ascii.rs`, score digits, pause
menu) is sprites from ascii.png, i.e. a texture.

### 2.3 Translation layer

- `TextCmd` gains `key: TextRef` (`Msg{file,entry,nth}`, `Spell{card,field}`, `PlayerSpell`,
  `Ending{file,line}`, `MusicCmt{track,line}`, `Builtin{id,args}`, `Dynamic`). Core sets it where it already knows
  the source (op index, card id, line). The raw `SjisString` stays. Core never sees translated text.
- Render side: `TextDb::get(&key) -> Option<&str>` (UTF-8). On a miss it decodes `raw` exactly as today, so vanilla
  output and the draw-parity images stay identical. Lookup and layout run at the same command point as today, so
  strip lifetime rules (10 §6) do not change.
- Encoding: translated text stays **UTF-8 and never goes through SJIS**. JIS X 0208 does contain Cyrillic (row 7), but
  its glyphs are fullwidth in Japanese fonts, it has no ё-style coverage guarantees, and the Shift-JIS byte-length
  formulas (`x = 256 − len·15/4`, right-align `len·15/2`) mean nothing for proportional Latin/Cyrillic. For translated
  text, layout uses the **measured** pixel width (what thcrap's `spell_align`/`menu_desc_align`/`stage_result_align`
  do). It keeps the byte formula on the vanilla path.
- Overflow per `TextTarget`: `squeeze | shrink | clip` in the pack manifest. Converter-time fitting:
  extra thcrap lines are joined into the last slot (reported by `pack-check`), so runtime never reflows.
- `Builtin` format strings (clear bonus etc., from stringdefs) are validated at import: the same printf
  specifiers in the same order, or the entry is dropped (fallback vanilla).
- Fonts: `FontProvider::FileFont` on a pack font, the same pixels on native and wasm. Default Latin +
  Cyrillic face: Noto Sans (or PT Sans Narrow for the 320-px msg strip). Japanese fallback inside the same stack, for
  untranslated lines. `pack-check` lists codepoints missing from the font.

### 2.4 Textures with baked text

Stage titles (`text/stg*txt.png`), boss name plates (`face_stNN_name.png`), menus (`title/*`, `front.png`),
results, ascii.png, the staff roll (`end/staff*.png`) and the info/ending pictures are **image overrides** through
`PresentView`. They are keyed by the ANM chunk image name (+0x1C, 03 §2.1) or the standalone jpg name, with the
same logical size (UVs from the logic ANM). thcrap's paths (`data/text/stg1txt.png`) map 1:1 to chunk
names. `title02.v1.00d.png` → strip the version suffix. If a replaced ascii.png has narrower glyphs
(`ascii_params CharWidth 13`), that is a per-pack presentation constant in the manifest. ascii positions are draw-only.
That claim needs checking against the AsciiManager spec section in run G0.

### 2.5 Pack format and selection

```
packs/lang_ru/   (dir or zip; later inside the AS1 .pak container)
  pack.toml        id, class = "presentation", language = "ru", source = "thpatch lang_ru <date>", [targets] overflow, [fonts]
  ATTRIBUTION.txt
  text/msg.json    {"msg1a.dat/0/3": "…"}   key = TextRef string, nth text op in the entry
  text/end.json  text/spell.json  text/musiccmt.json  text/builtin.json
  images/<chunk name>.png   files/<name>.jpg   fonts/*.ttf
```

The text is JSON (serde_json is already a dependency, and thcrap is JSON). This deviates from the PO files the mod design proposed. A `pot`/PO
export can come later for human translators. The converter needs the user's th08.dat, which it uses to turn thcrap's
`<time>_<n>` box keys into our `(entry, nth op)` keys by walking the vanilla msg file (10 §5.1), and end line indices
into `Ending{file,line}`. Selection: setting `game_text` (§3.2) → the pack with that `language`. If none is
installed, the game uses vanilla and the launcher shows a note.

## 3. Launcher i18n (ja, en, ru)

### 3.1 String tables

- English stays the source in the `Entry` table (`src/settings.rs:140`: `label`, `help`, `Group::title`,
  `Kind::Enum` choices). CLI `--help` stays English.
- New `src/i18n.rs` + `i18n/{ja,ru}.toml` (embedded with `include_str!`), keyed by stable ids:
  `entry.<key>.label`, `entry.<key>.help`, `entry.<key>.choice.<value>`, `group.<id>`, `ui.<id>` (launcher buttons,
  folder check, port menu `src/platform/portmenu.rs`). `tr(lang, id, en_fallback)`. A unit test checks that every
  `ENTRIES` key / group / choice has ja and ru strings, and that no orphan ids exist. A separate table rather than
  more `&'static str` fields keeps the 56-entry table readable and lets translators edit one file. A crate
  (`rust-i18n`) is an option, but a ~100-line TOML lookup is the smaller dependency.
- egui: Latin and Cyrillic are in egui's default font. Japanese needs a CJK fallback family. On native, load the
  font found by `text.rs` `FONT_PATHS` / `TH08_FONT`. On web, a build-time **subset** of Noto Sans JP limited to the
  glyphs of `ja.toml` (tens of KB). On Android the Compose system font covers everything.

### 3.2 Settings

- `language`: `Enum(["auto","ja","en","ru"])`, default `auto`, persisted, every platform. `auto` takes the system
  locale (`sys-locale` crate on native; `navigator.language` on web; `Locale.getDefault()` on Android) → ja/ru,
  else en.
- `game_text`: `Enum(["follow","ja","en","ru"])`, default `follow` (= `language`, `ja` = original). It is separate
  so that, for example, a Russian UI can still play the original Japanese. It is presentation only, and is read by the
  game through `CoreConfig` → renderer, never by logic.

### 3.3 Android Compose

`settings_schema` v3 carries translations from the same tables. `label`/`help`/group `title` become
`{"en": …, "ja": …, "ru": …}`, and enum entries get `choice_labels`. `Schema.kt` picks by the `language` setting.
That keeps a single source and nothing can drift, matching the existing "generated from the table" rule. Only the
app name and the few Kotlin-only strings go to `res/values-{ja,ru}/strings.xml`. The round-trip test in
`settings_schema.rs` is extended to the maps.

## 6. Decision (owner, 2026-11-04, final): nothing from thpatch is committed

Translations are fetched on demand, never stored in git: neither text nor images. `thcrap-import` (G3) is
language-generic (`--lang <code>`, `--list` = every lang_xx on srv.thpatch.net that has th08 files), caches downloads
per language and source revision under `target/thcrap/<lang>/` and builds a presentation pack (text JSON, images,
ATTRIBUTION.md with source, licence and revision). Partial translations fall back to the original per key. Personal
packages (`cargo xtask dist --assets packed`) bundle the packs chosen at build time; every launcher (desktop egui,
Android Compose, web) can list the languages available on the server and download / update a pack into the user's
config folder, the same way thcrap does, so `game_text` is not limited to en / ru. Fonts: the translation's own fonts
(patch.js `fonts`, th08.js `font`), downloaded on demand into the same cache and pack, falling back to the system
font; we never commit or ship them (a commercial face such as MyriadPro-Cond is used only from the user's own
download). Only a fallback font we ship ourselves must be OFL.
